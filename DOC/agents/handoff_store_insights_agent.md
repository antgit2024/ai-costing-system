## 1) 背景与目标（必须理解）

### 为什么要做这块
现有单品顺加算价无法承载“全店口径”（固定成本/广告费/活动折扣等），会出现低客单价产品“推导价不可卖”的结论，运营无法执行。

### 本模块的定位
把定价从单品算术升级为 **店铺月度经营策略系统**：

**Plan（计划）→ Scenario（模型/情景）→ Actual（实际录入）→ Variance（对比仪表盘）→ Pricing引用（算价页引用模型）→ AI建议（beta）**

模块归属：属于 **数据洞察/经营分析**（不应长期放在测试台/单品页里）。

## 3) 业务口径（默认值 & 必须保持一致）

### 店铺级默认值（Plan）
- 月 GMV 默认：600,000
- 目标净利% 默认：8%
- 店铺预设费率（%）：
  - 固定成本：15%
  - 广告费用：15%
  - 平台扣款：6.1%
  - 平台活动：10%（全年平均）
  - 快递费用：10%

### 关键约定
- MVP 为 **月度**（按月复盘，最快落地）
- 实际数据来源：**运营手动录入**
- 多店铺：天猫多店、京东多店，**店铺独立核算**
- Scenario：模板可复用；每月复制生成当月版本（留痕）
- 引流亏损池：默认用 **%**（金额可选硬止损）
- 成本项录入：**% + 金额**双输入，填一项自动换算另一项
- SKU 角色：不能被模型/品类固化；需要 **SKU级月度可调整**，同一模型不同图案可不同角色；但店铺仍有结构目标并预警偏离

## 4) 关键公式（实现与文档一致）

> 以 GMV 为分母（含税成交口径），详见 PRD。

- 贡献毛利池（CM Pool）：  
  `CM_pool = fixed + ad + target_profit`  
  `CM_pool% = CM_pool / GMV`

- 结构反推利润款所需贡献毛利率：  
  `cm_p = (CM_pool% - s_t*cm_t - s_b*cm_b) / s_p`

- 引流亏损池（%）：  
  `LossPool = GMV * traffic_loss_pool_pct`

## 5) 开发范围拆分建议（按里程碑推进）

### MVP-1：经营闭环（数据洞察模块）
- Store 列表
- 店铺月度 Plan（目标与预设费率）
- ScenarioTemplate + ScenarioMonth（模板复用 + 当月复制留痕）
- ActualSnapshot（月度录入 + 修订版本）
- Variance（差异表 + 贡献毛利分配图）
- 引流亏损池预警（创建/编辑 ScenarioMonth 时：>2%黄警，>5%红警）

### MVP-2：算价引用模型
- 算价页可选择 “店铺 + ScenarioMonth”
- 自动带入该模型的策略参数
- 输出单品“达标条件三段信息”

### MVP-3：AI建议（beta）
- 接入千问
- 按触发场景路由提示词（先三场景：固定成本超标 / 利润款占比不足 / 快递费超标）
- 输出固定结构模板（结论/归因Top3/动作清单/影响区间/风险前置）
