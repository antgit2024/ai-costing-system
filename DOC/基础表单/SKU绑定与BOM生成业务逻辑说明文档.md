# SKU绑定与BOM生成业务逻辑说明文档

## 一、数据源：发货单（订单明细）

### 1. 核心业务字段说明

#### 1.1 订单级别字段（整单维度）

| 业务字段 | 业务含义 | 数据特征 | 业务用途 |
|---------|---------|---------|---------|
| **付款时间** | 客户实际付款的时间 | 格式：YYYY-MM-DD HH:MM:SS | **成本核算的起始时间点**，用于计算某个时间段的订单成本和利润 |
| **完成时间** | 订单发货完成的时间 | 格式：YYYY-MM-DD HH:MM:SS | **成本核算的结束时间点**，用于计算某个时间段的订单成本和利润 |
| **数量合计** | 整单的商品总件数 | 整数，可能包含多个SKU的数量之和 | **统计用**：该客户本次订单一共买了多少件商品（不参与BOM计算） |
| **实付金额** | 客户实际支付的总金额 | 小数，单位：元 | **统计用**：该客户本次订单一共付了多少钱（不参与BOM计算） |
| **销售渠道** | 订单来源的店铺名称 | 文本，如"九斗云旗舰店"、"绮妙旗舰店"、"云舫旗舰店" | **店铺维度统计**：按店铺统计销售额、成本、利润 |

#### 1.2 SKU级别字段（单个商品维度）

| 业务字段 | 业务含义 | 数据特征 | 业务用途 |
|---------|---------|---------|---------|
| **货品编号** | 图片编号（产品系列编号） | 文本，如"J24121403"、"Q25102204" | **产品系列标识**：同一个图片可以做成多种产品（地垫、抱枕、桌布等） |
| **货品名称** | 店铺商品的标题 | 文本，店铺展示的商品名称 | **展示用**：给客户看的商品名称（不参与BOM计算） |
| **数量** | 购买该SKU的数量 | 整数，单个SKU的购买数量 | **BOM计算的倍数**：生成BOM后，所有物料需求 × 数量 |
| **单价** | 该SKU的原价 | 小数，单位：元 | **统计用**：原价（不参与成本核算） |
| **金额** | 该SKU的实际收款价格 | 小数，单位：元 | **收入核算**：扣除优惠后的实际收款金额 |
| **货品条码** | **唯一SKU ID** | **数字或文本，全局唯一** | **🔑 核心字段：绑定标准产品模型的唯一标识** |
| **交易规格** | 网店SKU的属性描述 | **文本，包含尺寸、颜色、材质等信息** | **🔑 核心字段：用于解析规格、提取token、触发变体规则** |
| **商品链接ID** | 网店商品的唯一ID | 数字，一个商品ID包含多个SKU | **商品维度统计**：统计某个商品（包含所有SKU）的销售数据 |

## 二、核心业务逻辑

### 2.1 SKU与标准产品模型的绑定关系

#### 业务场景
- 网店的每个SKU（货品条码）需要绑定到一个**标准产品模型**
- 标准产品模型定义了该SKU的**基准清单（兜底清单）**和**变体规则**
- 绑定关系是**一对一**的：一个SKU只能绑定一个标准产品模型

#### 绑定逻辑

```
输入：货品条码（SKU ID）
输出：标准产品模型ID

查询逻辑：
1. 根据"货品条码"查询SKU绑定表
2. 获取该SKU绑定的"标准产品模型ID"
3. 如果未绑定，则无法生成BOM，需要运营人员先配置绑定关系
```

#### 示例

| 货品条码 | 标准产品模型ID | 标准产品模型名称 | 备注 |
|---------|--------------|----------------|------|
| 5851557762667 | MODEL_001 | PS油画布画-有框画 | 九斗云旗舰店的装饰画 |
| 6119302655218 | MODEL_002 | 仿羊绒地垫 | 绮妙旗舰店的地垫 |
| 5955513932455 | MODEL_003 | 肌理提花抱枕 | 绮妙旗舰店的抱枕 |

### 2.2 交易规格的解析与Token提取

#### 业务场景
- "交易规格"字段包含了SKU的所有属性信息（尺寸、颜色、材质、工艺等）
- 需要从"交易规格"中提取**标准化的关键词（Token）**
- Token用于触发变体规则，决定最终BOM的物料组成

#### 交易规格的格式特征

**格式**：多个属性用分号`;`分隔，每个属性用冒号`:`分隔键值对

**示例**：
```
尺寸:40*60cm;颜色分类:Q25102203C仿羊绒地垫（素米边）
颜色分类:J24121403B;组合形式:画框+鳄鱼纹理+黑色小球+UV砂岩镂空竹编+烫金皮草;尺寸:小套约：50*70+30*30+44.5*34.5;外框类型:生态环保经典黑画框+复古外框（8222黑）
颜色分类:Q25102709G深苔漫织-黑色包边 45X45;尺寸:PP棉枕芯+枕套
```

#### Token提取逻辑

```
输入：交易规格（原始文本）
输出：Token列表（标准化关键词数组）

提取逻辑：
1. 解析"交易规格"字段，按分号";"拆分成多个属性
2. 对每个属性，提取关键信息（如尺寸数值、颜色代码、材质关键词等）
3. 查询"Token全局词典"，将提取的关键词映射到标准Token编码
4. 返回标准Token编码列表

Token词典匹配规则：
- 支持同义词匹配（如"024"、"24号"、"24#"都映射到"FRAME_024"）
- 支持模糊匹配（如"约50*70"提取出宽度50、高度70，计算面积、周长）
- 支持尺寸档位匹配（如面积0.35㎡ → SIZE_S）
```

#### 示例

| 交易规格（原始） | 提取的Token | 说明 |
|----------------|-----------|------|
| "尺寸:40*60cm;颜色分类:Q25102203C仿羊绒地垫" | [SIZE_S, MATERIAL_FLEECE] | 尺寸40*60=0.24㎡→小型；仿羊绒→羊绒材质 |
| "外框类型:生态环保经典黑画框+复古外框（8222黑）" | [FRAME_8222, COLOR_BLACK] | 8222画框；黑色 |
| "组合形式:画框+鳄鱼纹理+黑色小球+UV砂岩" | [FRAME_YES, TEXTURE_CROCODILE, BALL_BLACK, SANDSTONE_UV] | 有画框；鳄鱼纹理；黑色小球；UV砂岩 |
| "尺寸:约50*140;外框类型:024咖啡+向右推拉" | [SIZE_L, FRAME_024, COLOR_COFFEE, PUSH_PULL_RIGHT] | 大尺寸；024画框；咖啡色；右推拉 |

### 2.3 交易规格的变更控制规范

#### 业务风险
- "交易规格"字段的内容可能会变化（运营人员修改商品属性、新增SKU等）
- 如果规格变化导致Token提取错误，会导致BOM生成错误，进而导致成本核算错误

#### 运营规范

**允许变化的内容**：
1. **数值的微调**：如"约50*70" → "约49*71"（尺寸微调，不影响档位）
2. **同义词替换**：如"024画框" → "24号画框"（已在Token词典中配置同义词）
3. **顺序调整**：如"尺寸:50*70;颜色:黑色" → "颜色:黑色;尺寸:50*70"（顺序不影响提取）

**不允许变化的内容**：
1. **关键Token的删除**：如删除"024画框" → 会导致变体规则不触发，BOM错误
2. **关键Token的替换**：如"024画框" → "149画框" → 这是不同的SKU，应该创建新的货品条码
3. **属性键名的变化**：如"外框类型" → "画框类型" → 会导致解析失败

#### 变更控制流程

```
运营人员修改"交易规格"前：
1. 系统检测"交易规格"是否发生变化
2. 如果变化，触发"规格变更审批流程"：
   a. 对比变更前后的Token提取结果
   b. 如果Token列表发生变化 → 警告：可能影响BOM生成
   c. 如果Token列表不变 → 允许变更
3. 变更后，记录变更历史（变更前、变更后、变更人、变更时间、变更原因）
```

### 2.4 BOM动态生成逻辑

#### 业务场景
- 每个订单的每个SKU，需要根据"货品条码"和"交易规格"动态生成BOM
- BOM包含：物料清单、数量计算公式、工序清单

#### 生成逻辑

```
输入：
- 货品条码（SKU ID）
- 交易规格（规格文本）
- 数量（购买数量）

输出：
- 最终BOM（物料清单 + 数量 + 工序清单）
- BOM快照（包含trace，用于审计和对账）

生成步骤：
1. 根据"货品条码"查询绑定的"标准产品模型ID"
2. 读取该模型的"基准清单（兜底清单）"
3. 解析"交易规格"，提取Token列表
4. 查询该模型的所有"变体规则"，筛选出触发条件匹配的规则
5. 按优先级顺序，依次执行变体规则（替换物料）：
   - 遍历基准清单的每一行
   - 如果该物料在变体规则的"源物料ID"中 → 替换为"目标物料ID"
   - 否则 → 保持不变
6. 计算每个物料的数量（根据数量公式和尺寸参数）
7. 乘以购买数量，得到最终物料需求
8. 生成BOM快照，记录：
   - 订单号、SKU ID、交易规格、Token列表、触发的规则ID、最终BOM、生成时间
   - trace：每个物料的来源（基准清单 / 规则R001替换 / 规则R002增加）
9. 返回最终BOM
```

#### 示例

**输入**：
- 货品条码：5851557762667
- 交易规格：`颜色分类:J24121403B;组合形式:画框+鳄鱼纹理;尺寸:约50*70;外框类型:024画框`
- 数量：1

**处理过程**：
1. 查询绑定：5851557762667 → MODEL_001（PS油画布画-有框画）
2. 读取基准清单：
   - M149-149画框（数量=周长）
   - M002-2号挂扣（数量=2）
   - M010-5mm背板（数量=面积）
   - M020-宣绒布（数量=面积）
3. 解析规格：提取Token = [FRAME_024, SIZE_M]
4. 查询变体规则：
   - 规则R001：token=FRAME_024 → M149替换为M024，M002替换为M003
   - 规则R002：token=SIZE_M → 无匹配规则
5. 执行变体：
   - M149 → M024（024画框）
   - M002 → M003（3号挂扣）
   - M010 → M010（5mm背板，不变）
   - M020 → M020（宣绒布，不变）
6. 计算数量：
   - 尺寸50*70 → 面积=0.35㎡，周长=2.4m
   - M024：2.4m
   - M003：2个
   - M010：0.35㎡
   - M020：0.35㎡
7. 最终BOM：
   - M024-024画框：2.4m × 1 = 2.4m
   - M003-3号挂扣：2个 × 1 = 2个
   - M010-5mm背板：0.35㎡ × 1 = 0.35㎡
   - M020-宣绒布：0.35㎡ × 1 = 0.35㎡

**输出**：
```json
{
  "order_id": "JY202512210802",
  "sku_id": "5851557762667",
  "spec_text": "颜色分类:J24121403B;组合形式:画框+鳄鱼纹理;尺寸:约50*70;外框类型:024画框",
  "tokens": ["FRAME_024", "SIZE_M"],
  "triggered_rules": ["R001"],
  "bom": [
    {
      "material_id": "M024",
      "material_name": "024画框",
      "quantity": 2.4,
      "unit": "m",
      "source": "基准清单M149 → 规则R001替换"
    },
    {
      "material_id": "M003",
      "material_name": "3号挂扣",
      "quantity": 2,
      "unit": "个",
      "source": "基准清单M002 → 规则R001替换"
    },
```

## 三、成本核算时间段逻辑

### 3.1 业务场景
- 需要计算某个时间段（如2025年10月）的订单成本和利润
- 时间段的定义：根据"付款时间"和"完成时间"确定

### 3.2 时间段筛选逻辑

```
输入：
- 开始日期（如2025-10-01）
- 结束日期（如2025-10-31）

筛选逻辑：
方案A（按付款时间）：
  筛选条件：付款时间 >= 开始日期 AND 付款时间 <= 结束日期

方案B（按完成时间）：
  筛选条件：完成时间 >= 开始日期 AND 完成时间 <= 结束日期

方案C（按订单周期）：
  筛选条件：付款时间 >= 开始日期 AND 完成时间 <= 结束日期

建议：采用方案B（按完成时间）
理由：
1. 成本核算应该以"发货完成"为准（此时才真正发生成本）
2. 付款时间可能在上个月，但发货在本月，应该计入本月成本
3. 符合权责发生制的会计原则
```

### 3.3 示例

**需求**：计算2025年12月21日的订单成本

**筛选条件**：
```sql
完成时间 >= '2025-12-21 00:00:00' 
AND 完成时间 <= '2025-12-21 23:59:59'
```

**结果**：
- 包含所有在12月21日完成发货的订单
- 即使付款时间是12月20日，只要完成时间是12月21日，也计入

## 四、数据统计维度

### 4.1 不参与BOM计算的统计字段

| 字段 | 用途 | 统计维度 |
|------|------|---------|
| **数量合计** | 统计客户购买的总件数 | 订单维度 |
| **实付金额** | 统计客户支付的总金额 | 订单维度 |
| **货品名称** | 展示商品名称 | 展示用 |
| **单价** | 统计原价 | SKU维度 |

### 4.2 参与成本核算的字段

| 字段 | 用途 | 核算逻辑 |
|------|------|---------|
| **金额** | 该SKU的实际收入 | 收入 = 所有SKU的金额之和 |
| **数量** | 该SKU的购买数量 | 成本 = BOM物料成本 × 数量 |
| **销售渠道** | 店铺维度的成本核算 | 按店铺统计收入、成本、利润 |

### 4.3 商品维度统计

**用途**：统计某个商品（包含所有SKU）的销售数据

**逻辑**：
```
根据"商品链接ID"分组统计：
- 销售数量 = SUM(数量)
- 销售金额 = SUM(金额)
- 订单数量 = COUNT(DISTINCT 订单号)
```

**示例**：
- 商品链接ID：862744627935（法式复古风客厅装饰画）
- 包含多个SKU：5851557762667、5853184671015等
- 统计该商品的总销量、总销售额

## 五、关键业务规则总结

### 5.1 核心绑定关系

```
货品条码（SKU ID） 
  ↓ 一对一绑定
标准产品模型ID
  ↓ 包含
基准清单（兜底清单） + 变体规则
  ↓ 解析
交易规格 → Token列表
  ↓ 触发
变体规则 → 物料替换
  ↓ 生成
最终BOM（物料清单 + 数量）
  ↓ 乘以
购买数量
  ↓ 得到
物料需求 → 扣库存 + 成本核算
```

### 5.2 数据流转

```
订单数据（发货单）
  ↓ 提取
货品条码 + 交易规格 + 数量
  ↓ 查询
SKU绑定表 → 标准产品模型ID
  ↓ 读取
基准清单 + 变体规则
  ↓ 解析
交易规格 → Token列表
  ↓ 匹配
变体规则 → 触发的规则列表
  ↓ 执行
物料替换 → 最终BOM
  ↓ 计算
物料数量 × 购买数量 → 物料需求
  ↓ 落库
BOM快照（包含trace）
  ↓ 用于
扣库存 + 成本核算 + 对账审计
```

### 5.3 关键约束

1. **货品条码必须唯一**：同一个货品条码只能绑定一个标准产品模型
2. **交易规格变更必须审批**：变更前必须检查Token提取结果是否变化
3. **BOM生成必须落快照**：每次生成BOM必须记录快照和trace，用于审计
4. **扣库存以快照为准**：库存扣减、成本核算都以BOM快照为准，不受规则变更影响
5. **Token必须来自全局词典**：不允许自由输入，必须从Token词典中选择

## 六、给CURSOR的实施建议

### 6.1 数据表设计要点

**需要的核心表**：
1. **SKU绑定表**：货品条码 → 标准产品模型ID
2. **标准产品模型表**：模型ID、模型名称、基准清单ID
3. **基准清单表**：物料ID、物料名称、数量公式
4. **变体规则表**：规则ID、触发条件（Token）、源物料ID、目标物料ID
5. **Token全局词典表**：Token编码、Token名称、同义词列表
6. **BOM快照表**：订单号、SKU ID、交易规格、Token列表、触发规则、最终BOM、trace、生成时间

### 6.2 接口设计要点

**核心接口**：
1. **BOM生成接口**：
   - 输入：货品条码、交易规格、数量
   - 输出：最终BOM + BOM快照ID
2. **规格解析接口**：
   - 输入：交易规格（文本）
   - 输出：Token列表
3. **变体规则匹配接口**：
   - 输入：标准产品模型ID、Token列表
   - 输出：触发的规则列表（按优先级排序）

### 6.3 业务逻辑实现要点

1. **Token提取逻辑**：需要支持同义词匹配、模糊匹配、尺寸档位匹配
2. **变体规则执行逻辑**：只做"对等替换"（源物料ID → 目标物料ID）
3. **数量计算逻辑**：支持公式计算（如周长、面积）和固定数量
4. **BOM快照逻辑**：每次生成BOM必须落库，记录完整的trace信息

### 6.4 运营规范实施要点

1. **SKU绑定管理**：提供界面让运营人员配置"货品条码 → 标准产品模型"的绑定关系
2. **Token词典管理**：提供界面让运营人员管理Token（新增、修改同义词、废弃）
3. **变体规则管理**：提供界面让运营人员配置变体规则（条件、替换物料、优先级）
4. **规格变更审批**：当"交易规格"变更时，自动检测Token变化，如有变化则需审批
5. **BOM预演功能**：运营人员配置规则后，可以输入测试用例，预览生成的BOM

## 七、特别注意事项

### 7.1 交易规格的不确定性

**问题**：
- "交易规格"字段的格式不统一（有的用分号，有的用加号，有的用空格）
- "交易规格"字段的内容可能随时变化（运营人员修改商品属性）

**解决方案**：
1. **建立规格解析规则库**：针对不同的格式，建立不同的解析规则
2. **建立Token词典**：将所有可能的关键词都映射到标准Token
3. **建立变更审批流程**：变更前检测Token变化，有变化则需审批

### 7.2 BOM快照的重要性

**为什么必须落快照**：
1. **对账准确性**：库存扣减以快照为准，不受规则变更影响
2. **成本追溯**：可以追溯任何一个订单的BOM是怎么生成的
3. **问题排查**：出问题时，可以根据trace快速定位是哪个环节出错

**快照必须包含的信息**：
- 订单号、SKU ID、交易规格（原始文本）
- Token列表（解析结果）
- 触发的规则ID列表
- 最终BOM（物料ID、物料名称、数量、单位）
- trace（每个物料的来源：基准清单 / 规则R001替换）
- 生成时间

### 7.3 分阶段实施建议

**阶段一**（立即启动）：
1. 建立SKU绑定表（货品条码 → 标准产品模型ID）
2. 建立基准清单表（每个模型的兜底清单）
3. 建立简单的BOM生成逻辑（只用基准清单，不做变体）

**阶段二**（1-2周后）：
1. 建立Token全局词典
2. 建立规格解析逻辑（提取Token）
3. 建立变体规则表（只做"对等替换"）
4. 建立BOM生成逻辑（基准清单 + 变体规则）

**阶段三**（2-4周后）：
1. 建立BOM快照表（记录trace）
2. 建立规格变更审批流程
3. 建立BOM预演功能
4. 建立规则健康度监控

## 八、总结

### 核心要点

1. **货品条码是唯一标识**：用于绑定标准产品模型
2. **交易规格是动态输入**：用于解析Token、触发变体规则
3. **BOM生成是动态过程**：基准清单 + 变体规则 → 最终BOM
4. **BOM快照是对账依据**：扣库存、成本核算都以快照为准
5. **Token词典是基石**：所有规格解析、变体规则都依赖Token词典

### 实施原则

1. **先简单后复杂**：先做"只替换"，再扩展到"增加/删除"
2. **先手工后自动**：先手工配置绑定关系，再考虑自动识别
3. **先核心后周边**：先做BOM生成，再做成本核算、利润分配
4. **先落地后优化**：先用简单方案快速上线，再逐步优化
