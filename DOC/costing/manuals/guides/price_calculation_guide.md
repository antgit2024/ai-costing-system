## 0) 你在页面看到的是什么？

在打样管理 / 标准模型 / SKU 预览的"计算汇总"中，**v2 起展示 8 个价格字段**（v1 只有 4 个）：

| 价格字段 | 公式 | 给谁看 |
|---|---|---|
| **物料费** | Σ(物料用量 × BOM 单价) | 全员 |
| **人工费** | Σ(工序工时 × 全口径班组单价) | 全员 |
| **制造费** | (物料 + 人工) × 月度反推制造费率 | 全员 |
| **变动成本 cost_variable** | 物料 + 人工 | 运营促销下限 |
| **工厂全成本 cost_factory_full** | 变动 + 制造费 | 工厂内部考核 |
| **内部转移价 price_transfer** | 全成本 × (1 + 工厂目标利润率) | 运营采购成本 |
| **批发价下限 price_wholesale_floor** | 转移价 × (1 + 销售费用率 + 批发利润率) | 对外 B 端报价下限 |
| **零售建议价下限 price_retail_floor** | 转移价 / (1 - 运营毛利率 - 平台扣点 - 退货预提 - 广告费率) | 对内零售指导价 |

> **v1 只有"合计 = 物料 + 人工 + 制造费"**，运营拿这个数字去对外报价，被业务批"价格高得没法卖"——v2 通过分层把"工厂内部口径"和"运营对外口径"拆开了，运营用的是"内部转移价"而不是"工厂全成本"。

### 0.1 v2.1 新增：发货端三层利润口径（决策口径）

价格层是「面向报价」的口径，**做经营决策时（尤其是"砍不砍 SKU"）必须看「面向利润」的口径**。v2.1 在 `shipment_pnl_lines` 上明确输出**三层利润**：

| 利润层 | 公式（基于发货） | 经营含义 | 决策用途 |
|---|---|---|---|
| **贡献毛利一 GM1** `gross_margin_1` | 实收净收入 - 主材 - 辅料 - 包装 - 直接人工 - 变动制造费 - 运费 - 平台直接扣点 | 这一单**本身越卖越亏吗** | **GM1 < 0 → 优先涨价 / 替代材料 / 下架** |
| **经营毛利二 GM2** `gross_margin_2` | GM1 - 广告费分摊 - 退款售后预提 - 佣金 - 运费险 | 加上店铺运营动作还赚不赚 | GM2 < 0 → 检查广告/活动/退款/补贴策略 |
| **全成本利润三 NP3** `net_profit_3` | GM2 - 固定制造费分摊 - 管理费用分摊 | 会计全口径盈亏（只是结果指标） | **不直接作为砍 SKU 依据**（固定费用砍不掉） |

> **核心规则**：
> - 砍 SKU **优先看 GM1**（订单本身亏不亏）；
> - GM2 < 0 → 找运营动作问题；
> - NP3 < 0 但 GM2 > 0 → 多半是固定费用分摊问题，要看产能利用率，不是 SKU 问题。

字段命名对应 `shipment_pnl_lines`（详见 `pnl_analytics_module_design.md` §3）。

## 1) 物料费（Material Cost）

### 1.1 基础公式（保持 v1 兼容）

```text
小计 = 总用量(含损耗) × 单价
总用量(含损耗) = 总用量(不含损耗) × (1 + 耗损%)
本品用量 = 看面（可手工覆盖）
附加量 = 总用量(含损耗) - 本品用量
```

**v1 的痛点**：一律按"产品面积"算用量。120cm 原料切 70cm 产品和 90cm 产品，废料率分别是 42% 和 25%，但 v1 都按"产品面积 × 损耗率"算，**70cm 产品反而被算便宜了**——实际上 70cm 比 90cm 浪费更多原料。

### 1.2 v2 新增：原料幅宽与切割口径（area_with_cutting）

**触发条件**：物料类型为"卷材/板材"且 `Material.roll_width_mm` 已配置时，物料行的 `calculation_method = area_with_cutting` 自动启用。

**新公式**（v2.1 措辞修正：**标准下料占用面积**，不是实际耗料）：

```text
有效宽 = ceil(产品宽 / 原料宽) × 原料宽
标准下料占用面积 = 有效宽 × 产品长   # v2.1 命名（v2 旧称"实际消耗面积"已废弃）

举例（120cm 原料）：
- 70×70 产品：有效宽 = ceil(70/120) × 120 = 1 × 120 = 120cm
                标准下料占用 = 120 × 70 = 8400cm² = 0.84㎡
                （v1 按产品面积算 0.49㎡，少算 0.35㎡ ≈ 71% 损耗）

- 90×90 产品：标准下料占用 = 120 × 90 = 1.08㎡
                （v1 按产品面积算 0.81㎡，少算 0.27㎡ ≈ 33% 损耗）

- 110×110 产品：标准下料占用 = 120 × 110 = 1.32㎡
                  （v1 按产品面积算 1.21㎡，少算 0.11㎡ ≈ 9% 损耗）
```

> **v2.1 命名变更原因（已采纳外部评审）**：
> - "**标准下料占用面积**" = 单件理论 1:1 切割时的占用，**不是实际耗料**。
> - 实际耗料还要考虑：旋转排版、同日多订单合并裁切、卷头卷尾损耗、瑕疵返工等，这些 v2.1 不做、Phase 2 之后接生产/排版/裁切系统拿真值。
> - `Material.allow_rotate` 字段同步加进 schema（默认 false），Phase 2 实现"允许旋转后取 min(占用)"算法；v2.1 暂不消费。

**结论**：90×90 和 110×110 的"每㎡标准下料成本"接近真实，70×70 显著高于 90×90 ——这与同行附件的报价规律完全一致（同行 70×70 和 90×90 的"每㎡成本"几乎一样）。

### 1.3 边角料价值化（v2 简化版，v3 精细化）

为避免"全部按损耗算"过于保守，v2 引入边角料回收冲减：

```text
边角料长度 = (有效宽 - 产品宽) × 产品长
边角料价值 = 边角料长度 × 物料单价 × 边角料价值率

边角料价值率（按物料类型默认）：
- 整版幅料（可二次裁切）：0.80
- 不规则边角（仅可作小件）：0.30
- 完全废料（无法二次利用）：0.00（默认）

净物料成本 = 实际消耗成本 - 边角料价值
```

> v3 计划：对接库存模块，边角料回库为"次级原料"（FIFO 优先消耗）。

### 1.4 真实物料价格链路（v1 保持不变）

物料费来自真实物料主数据中的价格链路（系统优先走自动推导）：

- 采购/入库单价（供应链/宜搭同步或人工录入）
- 入库 → BOM 换算（单位/换算）
- 推导 BOM 单价（用于核算/扣库）

> 口径：BOM 单价会优先由"入库单价 ÷ 入库→BOM换算"推导；若存在手工覆盖或特殊定价，应要求有备注说明与可追溯依据。

### 1.5 虚拟物料（v1 保持不变）

虚拟物料按 bindings 展开到真实物料，再按 BOM 单价链路计算。

## 2) 人工费（Labor Cost）

### 2.1 基础公式（v1 保持兼容）

```text
分钟数 = base_minutes + unit_minutes × M
人工费 = 分钟数 × 单价(元/分)
```

### 2.2 v2 重大变化：班组单价从 finance API 反推

**v1 公式**（拍脑袋）：

```text
有效分钟 = 26 × 8 × 60 × 0.85 = 10608 分钟/月
元/分 = 班组月工资成本 / 有效分钟
```

**v1 痛点**：
- 月工资成本 **不含社保 / 公积金 / 福利**，对外解释会被指"成本算少了"
- 效率系数 0.85 太乐观（行业经验 0.65-0.75）
- 不区分班组类型（缝纫工和质检工的产出效率不一样）

**v2 新公式**：

```text
全口径人工成本 = 应发工资 + 社保(公司) + 公积金(公司) + 福利

有效分钟（按班组类型分档）:
- 缝纫/裁剪/印刷等高强度生产工: 0.70（默认）
- 质检/复检等低速精细工:        0.60
- 打包/出库等单一动作工:         0.80

有效分钟 = 26 × 8 × 60 × 效率系数

班组单价 = 全口径人工成本 / (人头数 × 有效分钟)
```

### 2.3 数据来源：finance-analyzer

每月 5 号 cron 自动从 `GET /api/v1/employees/labor-costs?period=YYYYMM` 拉取真实数据：

| finance 字段 | ai-costing 用途 |
|---|---|
| `salary_total` | 应发工资 |
| `social_insurance` | 社保（公司承担） |
| `housing_fund` | 公积金（公司承担） |
| `welfare_total` | 福利（餐补/住宿/交通） |
| `headcount` | 人头数 |
| `team_id` | 班组主键 |

详见 [finance_analyzer_integration_v1.md §3.2](../../blueprints/finance_analyzer_integration_v1.md)

### 2.4 三级回退（finance 不可用时）

```text
Level 1: finance API 拉取真实数据（推荐）
Level 2: ai-costing 本地 team_rate_settings 表手工配置
Level 3: 兜底 = 月工资 × 1.4(社保福利系数) / (26×8×60×0.7)
```

## 3) 制造费（Overhead）

### 3.0 v2.1 新增：制造费拆三类（变动 / 固定 / 异常）⭐

> **背景（已采纳第二轮外部评审）**：v2 把所有间接费混在一个综合费率里（22%-35%），存在三个失真：
> 1. **旺季/淡季波动**：旺季产能利用率高，固定费摊得薄，产品看着便宜；淡季摊得厚，看着贵——同一个 SKU 季节性波动。
> 2. **小规格 / 低价品被压死**：固定费用按"物料+人工"比例分摊，低价品分摊比例高，容易被误判要砍。
> 3. **异常费用污染常规成本**：返工 / 报废 / 停工事故按比例摊到所有 SKU，让正常产品看起来都亏。
>
> **v2.1 解决方案**：把"制造费"在 finance 端拆成 **3 个池**，每个池一个独立费率，独立分摊动因，独立用途。

| 类型 | 池子 | 包含什么 | 分摊动因 | 进入哪层利润 |
|---|---|---|---|---|
| **变动制造费** `overhead_variable` | 工厂变动费用池 | 电费、耗材、机针、胶水、设备易耗、生产辅助材料 | 按机器小时 / 标准工时 / 件数 / 标准下料面积 | **GM1** 贡献毛利一（订单本身） |
| **固定制造费** `overhead_fixed` | 工厂固定产能池 | 房租、设备折旧、车间管理人员工资、固定维护、保险 | 先归集到成本中心，再按"标准产能"分摊到品类（淡季摊不满 → 差异进 `monthly_cost_variance`） | **NP3** 全成本利润三（**不进 GM1**） |
| **异常制造费** `overhead_abnormal` | 异常专项池（与 `strategic_subsidy_log` 协同） | 返工、报废、停工事故、临时加急、质量事故、一次性整改 | **不默认摊给 SKU**，单独立项核销，归"异常 / 战略费用池" | 不进单 SKU，单独看月度报告 |

**对应 `category_overhead_rate_history` schema 升级**（与 `finance_analyzer_integration_v1.md §7.5.6` 同步）：

```sql
ALTER TABLE category_overhead_rate_history
  ADD COLUMN rate_type VARCHAR(16) NOT NULL DEFAULT 'combined',  -- 'variable' / 'fixed' / 'combined'
  -- combined 仅 v2.0 兼容，v2.1 起所有新数据必须填 variable / fixed
  ADD COLUMN allocation_basis VARCHAR(16) NOT NULL DEFAULT 'direct_cost',
  -- 'direct_cost'（v2.0 兜底） / 'machine_hours' / 'standard_minutes' / 'qty' / 'sqm_used'
  ADD COLUMN capacity_baseline DECIMAL(14,2);
  -- 固定费用专用：标准产能（如月标准工时数）；用于"淡季摊不满 → 差异进 variance"
```

> **关键纪律**：
> - **GM1 只看"变动制造费"**，固定制造费在 NP3 里出现；
> - **异常制造费永远不摊到单 SKU**，作为月度专项报告 + 财务追责依据；
> - Phase 1 至少先把"变动 / 固定"两类拆出来；"异常"在 Phase 2 接入财务的"异常费用池"接口后启用。

### 3.1 v2 重大变化：从 0.3 写死改为月度反推

**v1 公式**：

```text
制造费 = (物料费 + 人工费) × 0.30  # 写死
```

**v1 痛点**：30% 是拍脑袋值，可能严重偏离实际；多个代码位置写死（约 6 处），改动风险大。

**v2 新公式**：

```text
制造费率 = 当月间接费总额 / 当月直接成本（材料 + 人工）

制造费 = (物料费 + 人工费) × 制造费率_当月
```

**v2.1 新公式（拆三类后，与 §3.0 对应）**：

```text
变动制造费率 = 当月变动间接费总额 / 当月直接成本（材料 + 人工）  # 进 GM1
固定制造费   = 当月固定间接费总额 × (本品类标准工时 / 工厂总标准工时)  # 仅进 NP3
异常制造费   = 不摊到 SKU；按异常事件单独入"异常 / 战略费用池"

总制造费（仅展示） = 变动制造费 + 固定制造费
```

### 3.2 间接费科目清单（待 Phase 0 评审定稿）

> 最终清单需 Phase 0 评审时财务+代账会计共同确认。

### 3.3 行业经验区间（用作合理性校验）

| 工厂类型 | 制造费率参考区间 |
|---|---|
| 规模化/自动化高/管理摊薄 | 10%-20% |

- 月度环比波动 > 30%：钉钉报警，要求查找原因

## 4) 三层价格体系（v2 全新章节）

### 4.1 为什么需要三层

|  | 用途 | 不能等同于 |
|---|---|---|
| **工厂全成本** | 工厂内部考核盈亏 | 不能等同于报价（运营拿不下手） |
| **内部转移价** | 工厂→运营的内部结算 | 不能等同于全成本（工厂赚不到钱） |
| **批发价/零售价** | 对外销售 | 不能等同于内部转移价（漏掉销售费用） |

> 同行附件那家工厂"出厂价 26 元/㎡"对应的就是**内部转移价**；你们 v1 算出的 44.55 是**工厂全成本**——根本不是同一个东西。

### 4.2 完整公式

```text
# 第 1 层：工厂全成本（同 §3）
工厂全成本 = 物料费 + 人工费 + 制造费

# 第 2 层：内部转移价（工厂→运营）
内部转移价 = 工厂全成本 × (1 + 工厂目标利润率)

工厂目标利润率（按品类，存 price_layering_settings）：
- 常规品/标准化品: 8%-10%
- 难做的小批量/换线多: 12%-15%
- 定制品/非标: 15%-20%

# 第 3 层：批发价（对外 B 端）
批发价下限 = 内部转移价 × (1 + 销售费用率 + 批发目标利润率)
销售费用率 = 业务员提成 + 对账坏账 + 物流补贴 ≈ 5%
批发目标利润率 ≈ 10%

# 第 4 层：零售建议价（对内指导）
零售建议价 = 内部转移价 / (1 - 运营毛利率 - 平台扣点 - 退货预提 - 广告费率)
平台扣点（按平台）:
- 淘宝/天猫: 0.6%-5.4%
- 拼多多: 0.6%-3%
- 抖音: 5%-10%
- 京东: 2%-8%
退货预提（按品类）: 5%-15%
广告费率（按店铺策略）: 5%-30%
```

### 4.3 配置参数

所有比率存到表 `price_layering_settings`：

```text
id, category (nullable=全局兜底),
factory_margin_rate,     -- 工厂目标利润率
sales_expense_rate,      -- 销售费用率
wholesale_margin_rate,   -- 批发目标利润率
retail_min_margin_rate,  -- 零售最低毛利率
platform_fee_rate,       -- 平台扣点（按平台分行）
return_provision_rate,   -- 退货预提
ad_cost_rate,            -- 广告费率
effective_from, effective_to,
created_by, notes
```

详细管理流程见 [transfer_pricing_handbook.md](../transfer_pricing_handbook.md)。

## 5) 完整计算示例（同行 90×90 冰丝沙发垫对照）

### 5.1 输入

- 产品：冰丝沙发垫 90×90（580g/平方）
- 原料幅宽：120cm
- 物料标准㎡价：14 元/㎡（市场询价）
- 人工：缝纫工序 5 分钟/件
- 班组单价：4.42 元/分钟（v2 反推后）
- 月度制造费率：0.20（v2 反推后）
- 工厂目标利润率：10%
- 平台扣点：3%（淘宝）
- 运营毛利率目标：30%

### 5.2 v1 算法（旧）

```text
物料用量（按产品面积） = 0.81㎡
物料费 = 0.81 × 14 × (1 + 5%损耗) = 11.91
人工费 = 5 × (拍脑袋的 1.47) = 7.35  # v1 单价低估
制造费 = (11.91 + 7.35) × 0.30 = 5.78
工厂全成本 = 11.91 + 7.35 + 5.78 = 25.04

# v1 没有分层，运营直接拿 25.04 报价 → 还不够同行 17.985
```

### 5.3 v2 算法（新）

```text
物料用量（按 area_with_cutting） = 1.08㎡（120 × 90）
边角料长度 = (120-90) × 90 = 0.27㎡
边角料价值 = 0.27 × 14 × 0.30(回收率) = 1.13
物料费 = 1.08 × 14 × 1.05 - 1.13 = 14.74

人工费 = 5 × 4.42 = 22.10  # 全口径人工，乍看比 v1 高很多
                            # 但 v1 单价是错的（不含社保）
                            # 实际 v2 反映了真实人工成本

制造费 = (14.74 + 22.10) × 0.20 = 7.37  # 月度反推 20% 比 v1 的 30% 低
工厂全成本 = 14.74 + 22.10 + 7.37 = 44.21

# 注意：v2 全成本可能比 v1 高，因为人工口径变全了
# 但关键是后面的"内部转移价"和同行可比

内部转移价 = 44.21 × (1 + 10%) = 48.63 元

# ✗ 仍然偏高！需要诊断
```

### 5.4 差距诊断（这才是实战）

如果 v2 算出 48.63 仍高于同行 17.985，**这说明真实问题在数据**：

1. **人工 22.10 显然过高**：缝纫一片 90×90 沙发垫不该用 5 分钟。同行可能：
   - 用 1.5-2 分钟（流水线 / 模板辅助）→ 降到 6.6-8.8 元
   - 单价更低（不在江浙沪等高人工成本区域）

2. **物料 14.74 也偏高**：同行 580g/㎡ 冰丝按市场价应该 8-10 元/㎡（大宗采购更低），不是 14
   - 可能是你们小批量采购导致，需要集采

3. **制造费 7.37 接近**：这一项没问题

> **v2 的价值不是"自动算便宜"，而是"算得对"**——算出来贵就是贵，但能精确定位贵在哪里（人工 / 物料 / 制造费），让运营和工厂有共同语言去优化。

### 5.5 优化后的结果（理想态）

假设通过引入流水线模板把人工降到 1.5 分钟，集采把材料降到 9 元/㎡：

```text
物料费 = 1.08 × 9 × 1.05 - 0.27 × 9 × 0.30 = 9.48
人工费 = 1.5 × 4.42 = 6.63
制造费 = (9.48 + 6.63) × 0.20 = 3.22
工厂全成本 = 19.33
内部转移价 = 19.33 × 1.10 = 21.26

# 接近同行 17.985 的水平
```

## 8) 对外可信度话术（新增）

### 8.1 给运营的解释

> "v2 起，你们看到的'内部转移价'就是工厂给你们的进货成本，已经包含了工厂的合理利润。你们再加上自己的运营成本和利润，就是零售价。这个价格已经向同行水平看齐，可以安心报给客户。"

### 8.2 给工厂的解释

> "v2 起，制造费率不再是拍脑袋的 30%，而是每月从财务系统真实数据反推。你们能从'工厂全成本'看到自己的真实盈亏；'内部转移价 - 全成本'就是你们的工厂利润，每月与运营对账。"

### 8.3 给客户/审计的解释

> "我们采用标准成本法 + 月度差异分析。标准成本基于实际财务数据反推，每月与财务系统自动对账，差异超过 5% 自动报警并人工复核。物料用量按实际下料计算，而不是简化的产品面积。"

### 8.4 给老板的解释

> "v2 解决了 v1 的三个核心问题：(1) 制造费 30% 不准 → 改月度反推；(2) 运营拿不到合理价 → 引入三层价格；(3) 同尺寸成本不公平 → 改原料幅宽切割口径。落地后，理论成本与实际成本的月度差异 < 5%，运营和工厂都能用同一套数据对话。"
