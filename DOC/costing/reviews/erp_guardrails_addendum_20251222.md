# ERP 口径补强清单（Guardrails Addendum）— 发货时再解析主链优先

> 日期：2025-12-22（GMT+8）  
> 目的：把讨论中确认的“ERP级护栏/口径”固化为可长期引用的一页纸，避免后续迭代跑偏。  
> 适用范围：与当前主线“发货时再解析（spec_hash缓存）→ SKU→已发布标准版本绑定 → BOM快照/异常队列 → 可重试/可重跑”完全兼容。  
> 关联：`DOC/基础表单/BOM系统优化完整方案_最终版.md`、`DOC/costing/blueprints/sku_binding_bom_shipment_plan.md`、`DOC/costing/reviews/shipment_time_parse_review_phase0_phase1_20251222.md`

## 1) 单一真相（Single Source of Truth）：版本是可核算最小单元

- **绑定对象**：`SKU → published standard version`（绑定版本，不绑定“模型抽象”）
- **快照引用**：每条 `bom_snapshot` 必须携带/可追溯：
  - `bound_version_id`
  - `spec_hash`
  - `parser_version`
  - `external_line_key_hash` / `batch_id` / `shipment_line_id`
- **不回写原则**：任何规则/词典/模板/解析器升级 **不回写历史快照**；只能影响未来或“显式重跑”生成的新快照。

## 2) 重试/重跑是一等公民（必须先定义语义）

> 目标：避免“幂等做对了但业务改了绑定/规则后算不动”的死局。

建议在产品/接口/审计层固定三类动作（语义写死，便于对账解释）：

- **Retry Exceptions（重试异常）**：仅重试异常队列未解决项  
  - 产出：新快照（或将异常标记 resolved），但 **不删除历史异常记录**
- **Rerun Batch（重跑批次）**：对整批生成“子批次”并重跑  
  - 产出：一组新快照；允许与父批次比对差异（差异本身也是审计资产）
- **Rebuild Snapshot（单行重算）**：对单行强制重算（客服/纠错/复盘）

**审计硬字段**：任何重试/重跑必须带 `rerun_reason`（绑定补齐/词典升级/规则升级/人工纠错等），否则结果不可审计。

## 3) 编码是治理信号/增强信号，不是计算强依赖

“模型套模型 + 自动编码”非常适合解决 30% 复杂产品，但在主链阶段应定位为：

- **上游治理手段**：降低 `spec_text` 漂移带来的运营维护成本
- **解析增强信号**：作为解析器的优先信号/推荐绑定依据，而非唯一判定条件
- **质量监控指标**：埋码覆盖率、提取成功率、三字段一致性（组合形式/尺寸/外框类型）统计

这样既能逐步推行编码，也不会让历史/未治理SKU“全量阻断”。

## 4) 规格解析必须版本化 + 结构化输出 + 可回放解释

解析输出建议固定成结构化形态（而不是只输出 tokens）：

- **dimensions**：`width/height/area/perimeter`（含单位归一化口径）
- **tokens**：标准化 token 列表
- **explanations**：每个 token/维度的提取依据（可读解释）
- **parse_warnings**：缺字段、格式异常、列位移/表头不匹配等告警

并要求：
- `parser_version` 必须落库到 `spec_parse_snapshot`；升级后仍应支持“回放旧版本解析结果”用于追溯解释。

## 5) 异常队列从“错误码展示”升级为“可治理工作台”

异常的定义应与动作绑定（能让运营/财务“清积压”而不是“看日志”）：

- **SKU_NOT_BOUND**：缺少“SKU→已发布标准版本绑定”  
  - 动作：去绑定 / 批量绑定 / 重试异常
- **SPEC_PARSE_FAILED**：解析失败或缺尺寸  
  - 动作：查看原始行/解析日志 / 补规则样例 / 重试
- **BOM_GEN_FAILED / UOM_MISMATCH**：规则或主数据问题  
  - 动作：跳到版本清单/行级变体/物料主数据定位并修复

UI 原则：主表按 Excel 字段展示；系统字段（`spec_hash/bound_version_id/parser_version/trace`）进抽屉。

## 6) 成本核算口径必须提前定死（现在最便宜，后面最贵）

至少提前固化两类口径，并写入快照（trace 或显式字段）：

- **归属期口径**：按完成时间 `completed_at`（权责发生）
- **成本取值策略**：标准价/移动平均/批次价（可以先占位，但快照必须能记录“当时采用的策略”）

> 原因：一旦上线后再补口径，会导致表结构、接口、报表、回溯逻辑连锁返工。

## 7) 与“模型套模型 + 编码”扩展的接口边界（防跑偏）

主链跑通后再扩展 30% 复杂产品，建议遵守：

- **扩展能力只改变“如何得到 bound_version_id / 如何生成BOM”**，但不改变：
  - 发货导入幂等口径
  - 快照不回写原则
  - 重跑语义（产出新快照 + rerun_reason）
- 编码提取/子模型组合等扩展能力产生的新字段，应进入 trace/日志/监控，不破坏现有核算口径。

## 9) 主数据不同频治理策略（宜搭同步物料 ↔ 本地模型引用）

> 背景：宜搭物料可能千级规模、频繁变动；本地模型数量相对少但对“引用正确性”极度敏感。目标是防止“同名误选/重复料/旧料仍被引用/引用漂移”，并让问题可被发现与治理。

- **唯一键优先**：同步/引用应以“宜搭唯一ID或物料编码”为主键；禁止用名称当唯一键。
- **选择器防错**：模型/工艺模块的物料选择器默认仅展示“启用 + BOM 物料”，并提供分类/搜索，减少误选概率。
- **发布前强校验**：发布 `published standard version` 前校验引用物料是否存在/启用/单位口径可用；失败则阻断发布并提示定位路径。
- **健康检查**：提供报表/检查项（同编码多条、引用停用料、BOM 单价缺失、单位缺失/不一致），让治理可量化、可排期。
- **去重归并与引用迁移**：若发现重复料（同编码多条），应提供“归并/迁移引用”的治理动作，避免靠 UI 隐藏掩盖问题。
