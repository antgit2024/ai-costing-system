# PnL 模块异常事件日志

> **目的**：记录线上 / 测试 / 联调过程中所有异常事件（数据问题、报警、回退、事故、修复），让后人能查到"上次类似问题怎么解决的"。
> **维护规则**：事件发生时立即创建条目；状态闭环后写 root cause + 改进措施。
> **格式**：每个事件一节，倒序排列（最新在最上）。

---

## 事件状态约定

- 🔴 **OPEN** = 处理中，必须每天更新一次
- 🟡 **MITIGATED** = 已止血，根因调查中
- ✅ **CLOSED** = 根因明确 + 改进措施落地
- ⏸ **MONITORING** = 已修复，观察期

## 严重度定义

| 等级 | 标准 | 响应时间 | 升级条件 |
|---|---|---|---|
| **P0** | 老板看不到任何数据 / 全集团对账失败 / 大量金额错误 | 立即（<30 min） | 立即电话老板 |
| **P1** | 单店铺 / 单工厂数据错误 / 关键决策被误导 | 4 小时内 | 升级技术负责人 |
| **P2** | 个别 SKU 数据异常 / 报表延迟 / 报警阈值需调整 | 1 工作日 | — |
| **P3** | 优化建议 / 用户体验小问题 | 1 周 | — |

## 已知风险与"还没发生但要警惕的"清单

> 这一节是给后人看的"前车之鉴"——事先列出可能踩的坑：

### R1: finance 端 `accrual_period` 为 NULL 的历史流水
- **可能影响**：月度反推制造费率时漏算这部分
- **检测**：每月反推前先 `SELECT COUNT(*) FROM ledger_transactions WHERE accrual_period IS NULL AND created_at >= ?`
- **应对**：超阈值 → 钉钉告警 + 暂停反推等 finance 团队补数据

### R2: finance `company_name` 字符串前后空格 / 全角半角差异
- **可能影响**：`legal_entity_alias_map` 映射失败 → 主体过滤拿不到数据
- **检测**：建表时加 `CHECK (company_name = TRIM(company_name))`
- **应对**：所有进入映射的字符串先做 `.strip()` 处理

### R3: 月初 finance 没及时 rebuild `ledger_monthly_summaries`
- **可能影响**：每月 5 号 cron 反推用的是上上月数据
- **检测**：cron 启动前先调 `GET /api/v1/ledger/summaries/latest-period`，验证是否包含上月
- **应对**：旧数据 → 钉钉告警 + 跳过本次反推 + 等 finance 团队 rebuild 后人工触发

### R4: `cost_snapshot` 没锁住，物料价格改了导致历史利润漂移
- **可能影响**：老订单的利润数字今天变了，老板对账失败
- **检测**：每月对账时随机抽 10 个老订单，对比 `cost_snapshot.cost_material_main` 与 `shipment_pnl_lines.cost_material_main` 是否一致
- **应对**：差异 > 0.01 → 立即停止改物料价格 + 调查 snapshot 写入是否生效

### R5: 单 SKU 月销 < 30 件被打 `data_anomaly` 标签后**没有人去修**
- **可能影响**：长期卡住运营决策（看到一堆 anomaly 不知道哪些要修）
- **检测**：每周报"data_anomaly 数量周环比"
- **应对**：超阈值 → 创建数据修复任务给运营

### R6: `cost_allocation_rule` 规则被频繁修改导致历史数据"跳变"
- **可能影响**：老板看上月利润和这月利润的口径不一样
- **检测**：每月对账时检查 `cost_allocation_rule.effective_from` 是否有当月新增
- **应对**：规则变更必须财务 + 老板双签，且不能溯及既往

### R7: AI 周报（Phase 4）输出"砍 SKU"建议但没考虑组合影响
- **可能影响**：老板按建议砍引流款，店铺流量崩
- **检测**：所有"砍 SKU"建议必须经过 `OffshelfImpactDialog` 组合影响评估（Phase 3）
- **应对**：Phase 4 AI 输出"砍 SKU"建议时硬阻塞，必须先有 Phase 3 评估
