# 智能成本核算系统 - 讨论要点总结（完整版）

## 1. 核心问题与解决方案

### 1.1 核心痛点
-   **传统BOM的噩梦**：80万个SKU，如果每个SKU建立一个BOM（平均15条物料+人工），将产生约1200万条BOM记录，维护成本极高。
-   **SKU标题频繁变化**：运营团队为了优化营销，会频繁修改SKU标题，导致基于标题解析的成本计算失效。
-   **特殊尺寸物料不同**：小尺寸用薄板，大尺寸用厚板，超大尺寸加龙骨，传统BOM无法灵活应对。

### 1.2 核心解决方案
-   **公式化成本计算**：用几十个"产品模型"替代80万个"静态BOM"，通过公式动态计算任意尺寸的成本。
-   **SKU ID绑定**：不依赖易变的SKU标题，而是依赖永远不变的`SKU ID`与产品模型进行绑定。
-   **变体规则引擎**：通过配置规则，实现"小尺寸用薄板，大尺寸用厚板"等复杂逻辑的自动化处理。

---

## 2. 数据架构

### 2.1 三层架构（用户现有）
-   **第一层：物料管理**：维护所有原材料的采购价格（如"铝合金线条6.02元/米"）。
-   **第二层：工序**：定义标准化的生产单元（如"下料工序"），每个工序包含物料和人工。
-   **第三层：产品模型**：为每个产品大类建立模型，引用一组工序。

### 2.2 最终决策
-   **保留三层架构**：工序封装了"物料+人工"的完整生产知识，具有复用价值。
-   **工序=物料+人工**：工序是一个完整的、不可分割的整体，变体规则只做"整体工序替换"或"物料替换"（当工序不变时）。

---

## 3. 产品模型的计算方式

### 3.1 三种计算模式（用户现有）

| 计算模式 | 说明 | 适用场景 |
| :--- | :--- | :--- |
| **比例** | 根据尺寸自动计算成本 | 画、桌布等按尺寸定价的产品 |
| **一口价** | 无需计算，直接按固定价格 | 代工类产品 |
| **独立** | 直接按物料和人工累计 | 时钟类的固定尺寸产品 |

### 3.2 标准尺寸
-   所有"比例"模式的产品模型，默认基于**1米×1米**的标准尺寸进行配置。
-   实际计算时，根据订单的真实尺寸，按比例放大或缩小。

### 3.3 计量方式（三种）

| 计量方式 | 说明 | 计算公式 | 适用物料 |
| :--- | :--- | :--- | :--- |
| **周长** | 按产品周长计算消耗 | `(宽+高)×2 × 单价 × (1+耗损率)` | 画框线条 |
| **面积** | 按产品面积计算消耗 | `宽×高 × 单价 × (1+耗损率)` | 画芯、背板 |
| **数量** | 固定数量，与尺寸无关 | `固定数量 × 单价` | 挂钩、螺丝 |

### 3.4 管理费用
-   在物料成本和人工成本的基础上，额外加上**30%的管理费用**。
-   最终成本 = 物料成本 + 人工成本 + 管理费用（30%）

## 4. 变体规则引擎

### 4.1 最终决策：极简版
-   **核心原则**：只支持"物料替换且工序不变"的简单场景。
-   **复杂场景**：如果物料变化导致工序流程差异巨大（如铝合金→实木），直接新建独立模型。

### 4.2 三种触发类型

| 触发类型 | 说明 | 示例 |
| :--- | :--- | :--- |
| **字符匹配** | 从订单SKU属性中抓取特定字符 | IF SKU属性包含"PS画框" THEN 替换"铝合金线条"为"PS线条" |
| **面积计算** | 根据产品面积判断 | IF 面积 > 1.5平方 THEN 替换"5mm薄板"为"8mm厚板" |
| **周长计算** | 根据产品周长判断 | IF 周长 > 4米 THEN 添加"木质龙骨"物料 |

### 4.3 两种执行动作

| 执行动作 | 说明 |
| :--- | :--- |
| **替换物料** | 将工序中的某个物料替换为另一个物料 |
| **添加物料** | 在工序中新增一个物料（如加龙骨） |

---

## 5. SKU与模型的绑定

### 5.1 首次上架标准化
-   **运营团队的唯一硬性要求**：新品上架时，使用一次标准化的SKU标题。
-   **AI自动识别**：系统通过AI读取SKU标题和商品描述，自动识别其成本特征（如画框类型、工艺、尺寸），并与`SKU ID`绑定。

### 5.2 后续自由修改
-   一旦绑定完成，运营团队可以天马行空地修改SKU标题以优化营销，系统完全不受影响，因为它只认`SKU ID`。

### 5.3 异常预警
-   如果成本计算出现异常（如成本突然暴涨），系统自动发出预警，提醒财务团队进行人工复核。

---

## 6. 订单处理与物料统计

### 6.1 订单同步
-   **方式一**：定时（如每15分钟）从吉客云ERP API拉取"已发货订单"和"退货单"。
-   **方式二**：在管理后台提供Excel导入功能，支持批量导入订单。

### 6.2 成本计算时机
-   **实时计算**：订单同步到本地后，成本计算引擎立即为每个订单计算成本。
-   **批量处理**：支持一次处理成百上千个订单。

### 6.3 物料消耗记录
-   成本计算引擎在计算成本的同时，**自动生成并存储物料消耗明细**到`order_material_consumption`表。
-   **存储粒度**：订单级独立存储（每个订单都有独立的物料消耗记录），而不是合并存储。

### 6.4 月度物料统计
-   月底，对`order_material_consumption`表进行简单的汇总查询（`GROUP BY material_id`），即可得到本月所有物料的"理论总消耗"。
-   与仓库盘点后的"实际消耗"进行对比，生成《成本差异分析报告》。

---

## 7. 数据存储方案

### 7.1 最终决策：本地为核心，宜搭为辅助
-   **宜搭**：只作为"基础物料信息"（编码、名称、最新采购价）的只读数据源。
-   **本地数据库**：存储所有核心数据，包括工序、产品模型、变体规则、SKU映射、订单成本、物料消耗等。
-   **同步服务**：定时将宜搭的物料数据同步到本地数据库。

### 7.2 数据量优化
-   **订单物料消耗数据**：虽然数据量会随订单增长，但通过分区存储、定期归档、建立汇总表等策略，完全可控。
-   **对比传统BOM**：传统BOM需要立即创建2000万条记录，而我们的方案是按需增长，初期数据量远小于传统BOM。

---

## 8. 双轨成本核算

### 8.1 理论成本（实时计算）
-   **新品上架时**：系统自动计算该SKU的"标准成本"，供运营团队定价参考。
-   **订单下单时**：系统为每个订单实时计算"理论成本"，用于日常毛利监控。

### 8.2 实际成本（月度核算）
-   **月底盘点后**：根据`月初库存 + 本月采购 - 月末库存`，计算每种物料的"实际消耗"和"实际单位成本"。
-   **成本差异分析**：将"实际消耗"与"理论消耗"对比，找出价格差异、用量差异、盘点差异。
-   **实际成本分摊**：将"实际成本"按比例分摊回本月的每一笔订单，得到最真实的订单利润。

---

## 9. 核心数据库表（简要）

-   `materials`：物料基础信息表（从宜搭同步）
-   `processes`：工序表
-   `process_materials`：工序-物料关联表
-   `process_labors`：工序-人工关联表
-   `product_models`：产品模型表
-   `model_processes`：模型-工序关联表
-   `variant_rules`：变体规则表
-   `sku_model_mapping`：SKU-模型映射表
-   `sales_orders`：销售订单表（从ERP同步或Excel导入）
-   `order_costs`：订单成本表
-   `order_material_consumption`：订单物料消耗明细表

## 10. 实施路线图

**第一阶段：基础架构与核心功能（4周）**
-   搭建本地服务器环境。
-   完成数据库表结构设计。
-   开发管理后台的核心功能：工序管理、模型管理。
-   开发数据同步服务。

**第二阶段：计算引擎与订单处理（3周）**
-   开发成本计算引擎的核心计算逻辑。
-   实现订单成本和物料消耗的自动化计算与存储。

**第三阶段：统计分析与变体规则（3周）**
-   开发统计分析中心的报表功能。
-   开发极简版变体规则引擎及配置界面。

**第四阶段：数据初始化与试运行（2周）**
-   协助业务团队完成初始数据的录入。
-   系统与现有流程并行试运行。

**第五阶段：全面上线与优化**
-   正式切换到新系统。
-   根据用户反馈，持续优化。
