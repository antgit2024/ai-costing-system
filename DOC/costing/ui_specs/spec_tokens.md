# 交易规格 Token 规范（MVP）

本文定义交易规格（`spec_text`）中可嵌入的“可解析 Token”，用于在 ERP 条码/上游结构化字段尚未稳定前，让运营通过**对客最新的交易规格**驱动解析与核算。

## Token 列表

### 1) `B-XXXXAA`（套装模板/合并器）

- **语义**：按套装模板（bundle template）生成合并 BOM（多模型/多尺寸组合）。
- **来源**：在“产品上架（测试台）→ 多模型测试”录入组件后点击“保存为套装编码”生成。
- **触发行为**：当交易规格包含套装短码（`B-XXXXAA` 或兼容格式）时，后端将读取模板并调用多模型合并器生成合并 BOM（不依赖尺寸解析）。
- **编码结构**：`B-` + 4 位 `CODE` + 2 位 `selector`（AA/AB/AC...）。
  - 示例：`B-K8F3AA`（选择短语预设 AA）
  - 可选：`B-K8F3`（不指定 selector，按短语命中逻辑走默认匹配）
- **兼容**：
  - 仍兼容旧格式：`B:CODE(:A)`、`BUNDLE:CODE(:A)`、`B-CODE(-A)`
  - `spec/parse` 会统一输出内部规范 token：`B:CODE` 与（如有 selector）`B:CODE:A`，供后端逻辑使用。

### 2) `M:PI5`（单模型类别提示）

- **语义**：标识该交易规格属于某个“模型类别”（如 PI5）。
- **用途**：用于提示/路由/校验；不作为唯一版本锁定依据。
- **兼容**：系统仍会输出历史 token `MODEL:PI5`，并同时输出 `M:PI5`。

### 3) `V:<model_version_id>`（版本锁定，预留）

- **语义**：在交易规格中明确锁定某一个标准版本（`model_version_id`），用于复现与灰度。
- **优先级**：低于 `B:`，高于 `M:`。
- **说明**：MVP 阶段可先只定义规范；是否启用与是否提供短码映射视后续需求决定。

## 解析优先级（从高到低）

1. **`B:`**：只要命中即走套装模板合并器（多模型合并）。
2. **`V:`**：命中则锁定标准版本生成 BOM（单模型）。
3. **`M:`**：仅做模型类别提示/校验；不保证唯一定位版本。
