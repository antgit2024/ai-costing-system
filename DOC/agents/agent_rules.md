## Agent 统一规则（防慢/防崩/防丢上下文）

> 适用：@Planner / @Frontend Agent / @Backend Agent / @Docs Agent / @Data Agent  
> 目标：把“上下文”从聊天迁到仓库；任何新 Agent 10 分钟内可恢复工作。

### 0) 只读工作集（禁止全仓扫描）

- **只允许读取**：`DOC/agents/workset.md` 列出的文件/目录（5–20 个）。
- 任何需要扩展阅读的内容：先更新 `workset.md`，再读文件。

### 1) 大文件“永不直喂”

- 禁止直接读取/粘贴超大导出/日志（例如 `DOC/index/前端崩4cursor_.md`）。
- 必须先提炼：只提取 Top-N 片段到小文件（`DOC/index/extracted/`），并在 `DOC/agents/state.md` 记录提炼件路径。

### 2) 每轮只交付一个可验收产物（强制闭环）

- 一轮只做一种产物：**一个页面/一个组件/一个接口/一份文档**。
- 必须写清：**完成标准 + 1 条验证命令**（写进 `DOC/agents/state.md`）。
- 未达标不扩范围，不并行开新坑。

### 3) 严控“大 diff / 跨文件风暴”

- 一次只改一个主题；避免几百文件 diff 导致交互层卡顿/崩溃。
- 能“先加薄封装再迁移”的，优先薄封装，逐文件替换。

### 4) 统一恢复包（崩了也能继续）

每次进入一个新任务/新阶段，必须维护以下 4 个文件（短小、稳定）：

- `DOC/agents/state.md`：当前分支/当前改动点/未完成清单（≤15 行）+ 最近一次**已确认快照**路径
- `DOC/agents/commands.md`：一键复现命令（build/test/curl）
- `DOC/agents/known_issues.md`：已知坑/绕过
- `DOC/agents/workset.md`：允许读取的工作集清单

### 5) 输出限流（默认短结论 + 指向性引用）

- 默认只输出：结论、步骤、文件路径/函数名/行号。
- 日志/大表：只给“前 20 行 + 摘要 + 保存到的文件路径”。

### 6) 时间与时区口径（避免误回滚）

- 所有“今天/昨晚/几点”的口径统一用 **北京时间（GMT+8）**。
- 如果需要从导出文件恢复，以导出头部的 `GMT+8` 时间为准；不要凭感觉回退到更早版本。
